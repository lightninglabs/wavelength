# swaprpc

## Purpose

Generated gRPC/REST/mailbox-RPC stubs for `SwapService`, the external swap
server API consumed by the client SDK: Lightning<->Ark swaps (in-swap/
out-swap), channel-ID allocation for Lightning-to-Ark receives, and durable
credit funding/redemption/listing. Proto source: `swaprpc/swap.proto`
(REST-gateway rules in `swap.yaml`). Generated stubs plus one hand-written
file (`credit_account_auth.go`) holding the canonical digest and signing
transcript for account-scoped credit requests, so client and server derive
the same bytes from the same proto without either side owning the format.

## Key Types

- `SwapServiceClient` / `SwapServiceServer` — standard gRPC client/server
  interfaces.
- `SwapServiceMailboxClient` / `SwapServiceMailboxServer` — durable-mailbox
  transport bindings (`mailbox/rpc.RPCClient`/`Router`) for the same RPCs.
- `SettlementType` — which path backs a swap: `LIGHTNING`, `IN_ARK`,
  `CREDIT`, or `MIXED` (funded by both a vHTLC and reserved credit).
- `SwapMailboxEvent` — oneof wrapper for server-pushed mailbox events
  (`OutSwapHtlcEvent`, and others as added) delivered outside the
  request/response RPCs.
- `CreditOperationState` / `CreditOperationType` — externally visible FSM
  states/kinds for durable credit funding, pay, redemption, and receive
  operations.
- Request/response messages per RPC (`CreateInSwapRequest/Response`,
  `QuoteInSwapRequest/Response`, `CreateCreditRequest/Response`,
  `RedeemCreditRequest/Response`, `ListCreditsRequest/Response`,
  `AuthorizeInSwapRefundRequest/Response`,
  `AcknowledgeOutSwapHtlcRequest/Response`,
  `SignInSwapForfeitRequest/Response`,
  `SubmitOutSwapForfeitSignatureRequest/Response`,
  `RequestChannelIdRequest/Response`).
- `CreditAccountAuthorization` — per-request authorization carried on the six
  account-scoped requests (`RequestChannelId`, `CreateInSwap`, `QuoteInSwap`,
  `CreateCredit`, `RedeemCredit`, `ListCredits`). Holds `ExpiresAtUnix`,
  a 32-byte `Nonce`, and the Schnorr `Signature`.
- `CreditAccountRequestDigest(req)` (`credit_account_auth.go`) — canonical
  `(digest, accountKey)` for one account-scoped request. Clears the
  authorization field on a clone, serializes deterministically, and tags the
  `method || 0x00 || encoded` transcript with `CreditAccountRequestTag`.
- `CreditAccountAuthMessage` / `CreditAccountAuthDigest` — the transcript and
  BIP-340 tagged digest the identity key actually signs:
  `accountKey || requestDigest || expiresAt (big-endian u64) || nonce` under
  `CreditAccountAuthTag`.
- `CreditAccountAuthorizationForRequest` / `SetCreditAccountAuthorization` —
  typed get/set over the six supported requests; both reject any other
  message type rather than silently no-oping.
- `CreditAccountNonceSize` (32) and `CreditAccountMaxAuthTTL` (5m) — the
  nonce length and the ceiling a verifier applies to a supplied expiry.

## Relationships

- **Depends on**: `mailbox/rpc` (mailbox-RPC runtime types used by the
  generated mailbox client/server), `google.golang.org/grpc`,
  `grpc-ecosystem/grpc-gateway/v2` (REST gateway in `swap.pb.gw.go`),
  `btcd/chainhash` + `protobuf/proto` (tagged hashing and deterministic
  marshaling in `credit_account_auth.go`).
- **Depended on by**: `sdk/swaps` (`grpc_conn.go`, `out_swap_mailbox.go` —
  typed clients for the swap FSM; `credit_account_auth.go` stamps the
  authorization), `waved` (`rpc_wallet.go` signs the transcript with the
  daemon identity key), `sdk/ark` (`SignCreditAccountAuth` passthrough),
  `rpc/restclient` (REST transport adapter). `swapclientserver` implements
  `rpc/swapclientrpc`, not this package — only its tests import `swaprpc`.

## Invariants

- **Never edit generated code** (`swap.pb.go`, `swap_grpc.pb.go`,
  `swap.pb.gw.go`, `swap_mailboxrpc.pb.go`) — regenerate via `make rpc` after
  editing `swap.proto` or `swap.yaml`.
- `SettlementType.SETTLEMENT_TYPE_UNSPECIFIED` (0) is treated as Lightning
  for backward compatibility with older server responses; do not repurpose
  the zero value.
- `SwapMailboxEvent` is a proto oneof: read the populated variant, don't
  assume `OutSwapHtlcEvent` is the only case as new event kinds are added.
- `credit_account_auth.go` is hand-written and NOT regenerated by `make rpc`;
  adding an account-scoped RPC means adding a case to all three switches
  (`unsignedCreditAccountRequest`, `SetCreditAccountAuthorization`,
  `CreditAccountAuthorizationForRequest`). The default arm errors, so a
  missed case fails closed at the signer rather than shipping an unsigned
  request.
- The request digest is taken over the request with its authorization
  **cleared**, so the signature never commits to itself and a verifier can
  recompute the same bytes from what it received. Marshaling is
  `proto.MarshalOptions{Deterministic: true}` — the digest is only stable
  because of that flag, not because protobuf encoding is canonical.
- The full method name is prefixed into the transcript with a `0x00`
  separator, so a signature for one RPC cannot be replayed against another
  RPC whose request happens to encode identically.
- The two tags (`CreditAccountRequestTag`, `CreditAccountAuthTag`) are wire
  contract: changing either invalidates every in-flight authorization and
  requires both sides to ship together.
- `CreditAccountMaxAuthTTL` bounds validity even when a caller supplies a
  far-future `ExpiresAtUnix`; a verifier must apply the cap rather than
  trusting the field.
